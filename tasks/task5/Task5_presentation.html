HOW WE SPLIT THE TESTS

Unit or integration: one rule keeps them apart

Unit

20

One function, a known input, an asserted output.

Nothing is read from disk. To test classify() alone, the real model is swapped for a fake that always answers 0.2 / 0.7 / 0.1, so the right answer is known in advance.

Integration

15

Real parts working together.

The saved model file, our module, the data contract, the frozen data split and the recorded results, checked against each other.

The rule: if a test loads a real file, it is an integration test. Otherwise it is a unit test.

Group 7 · Task 5 · Testing

3

(0:45) The rubric marks us down if a unit test is really a component test, so we used one simple rule. A unit test never touches a file: for classify we replace the real model with a small fake model with fixed probabilities, so the test checks only our code, picking the top class and returning the right types, not scikit-learn. An integration test uses the real saved model, the real data split and the recorded results together. Counts: 20 unit (7 FR-1, 9 FR-14, 4 interface contract tests) and 15 integration (8 Model 1, 6 frozen split, 1 threshold config).

(0:40) These guard the data every other number depends on. The split was made once with seed 42 and committed; its manifest records a sha256 fingerprint of each file. If anyone regenerates or edits the split, the checksum test fails and tells us that metrics from before and after are no longer comparable. WHAT TESTING REVEALED

Three problems found before anyone used the module

5 of 386

A crash on real data

Dev courses with no intro arrive as NaN, and classify() crashed on them. Fixed, now unit-tested.

1.7.2 / 1.9.1

A version mismatch

The model was saved with scikit-learn 1.7.2; our environment installed 1.9.1. Pinned to 1.7.2: no warnings.

0.31

Low confidence

The median confidence on dev. A 0.5 threshold would hide 86% of courses; 0.2 keeps 85% at 0.865 accuracy.

Group 7 · Task 5 · Testing

Backup

Backup slide for questions. One: pandas reads an empty cell as NaN, a number, not as an empty string; 5 dev courses have no intro and the first version crashed on them. Two: the saved model was pickled with scikit-learn 1.7.2 and the unpinned environment installed 1.9.1. Results were identical, we checked, but scikit-learn does not promise that, so we pinned the version. Three: with 11 categories the model spreads its probability, so even correct answers have low confidence, for example 0.29 for "Learn Spanish". Courses above 0.3 are right 90 percent of the time. This is direct input for the FR-13 threshold card.
