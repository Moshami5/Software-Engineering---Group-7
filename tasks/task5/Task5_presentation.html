Backup

Backup slide for questions. A test that can never fail proves nothing, so we checked ours. Run on 9 Nov: changing greater-or-equal to greater-than in passes() and running the whole suite gave 1 failed, 170 passed. The integration tests did not notice, because the real models never produce a score exactly equal to a threshold. That is the case for writing boundary tests at unit level: they test the rule itself, not the data we happen to have. After the check we restored the file and all 171 pass again.

WHAT TESTING REVEALED

Three problems found before anyone used the modules

5 of 386

A crash on real data

Dev courses with no intro arrive as NaN, and classify() crashed on them. Fixed, now unit-tested (U4).

“;” vs “\n”

Synonyms read as one

One ESCO file separates alt labels with “;”, the other with newlines. Model 2 now splits on both (U5).

0.31

Low confidence

Median Model 1 confidence on dev. A 0.5 threshold would hide 86% of courses; 0.20 keeps 85% at 0.865 accuracy (I1).

Group 7 · Task 5 · Testing

Backup

Backup slide for questions. One: pandas reads an empty cell as NaN, a number, not as an empty string; 5 dev courses have no intro and the first version crashed on them. Two: skills_clean.csv separates synonyms with semicolons and skills_en.csv with newlines; the notebook only split on newlines, so each skill's synonyms were read as one long label. Three: with 11 categories the model spreads its probability, so even correct answers have low confidence. That finding set the category threshold at 0.20 instead of a guessed 0.5, and I1 tests both sides of it.
